# 标题

开源 TaskQuay：在 ChatGPT 中调用本机 Codex，查看任务和 Token 用量

# 正文

大家好，最近我在尝试让 ChatGPT 分析问题、安排任务和验收，再把需要实现的代码工作交给本机 Codex。

任务多了以后，几个问题比较明显：不同代理反复读取相同的上下文；多个任务同时写文件或编译，需要返工；聊天结束了，却找不到这次任务的 Codex 用量和验收记录。

我基于 **[Waishnav/DevSpace](https://github.com/Waishnav/devspace)** 做了一些修改，整理成 **TaskQuay**。上游提供本地 MCP 执行能力，这个分支增加任务管理、用量统计、会话复用和执行状态检查。

**项目地址：[github.com/wrfgup/taskquay](https://github.com/wrfgup/taskquay)**

## 如何工作

主控可以先通过 MCP 看目录、读源码、搜索文本，检查已有日志和测试回执。需要 Codex 时，再把目标、相关代码、已确认的信息和待验证事项交给它。后续修改优先继续相关会话。

这样可以减少重复探索和无关上下文，但交给 Codex 的材料仍会计入输入 Token。实际能节省多少，需要看具体任务的用量和结果。

## 增加的功能

- **项目任务台**：默认从本机访问 `/console/`，查看任务来源、执行状态、验收证据、关联会话和用量。主控直接完成、没有调用 Codex 的任务也能留下记录。
- **Token 回执**：使用提供方的用量事件，分别显示完整、部分、未知和未调用。缺失统计保持未知，历史会话用量不归入新任务；这些数字也不等于订阅余额或账单。
- **并行协调**：只读任务可有限并行，默认最多两个；同一工作目录的写入独占，共享构建输出和设备另行协调。超额任务在本地排队，等待时不启动模型推理。
- **会话复用与整理**：相关工作继续已有线程，独立审查可另开上下文。归档或恢复受管会话时，先预览范围，再确认执行；活动任务、有外部续写或归属不明的聊天会被跳过。

## 使用限制

项目还在早期阶段，任务安排和验收需要主控负责，目前没有固定的 Token 节省比例可供承诺。

返回给主控的文件内容和委派给模型的材料会离开本机，请按对应服务的权限和隐私要求使用。Shell 以本机用户权限运行，工作区路径校验和任务锁不构成系统级沙箱。

归档流程已有夹具测试，但此前的零推理空线程实验未完成真实恢复验证。正式使用前，请先在自己的 Codex 实例中用新建的测试会话验证，保留重要聊天。归档不会停止后台进程。

产品名为 TaskQuay，兼容命令和配置目录仍使用 `devspace`。请按双语 README 从本分支源码运行，上游 npm 包尚未包含这些改动。
