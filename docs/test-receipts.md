# 生成测试收据

从源码工程运行：

```powershell
pnpm exec tsx scripts/test-with-receipt.ts
# 或仅运行明确列出的工程内测试：
pnpm exec tsx scripts/test-with-receipt.ts src/test-receipt.test.ts
```

该命令启动一次新的 Node 测试运行，统计本轮结果，不调用模型。默认选择 `src` 内全部 `.test.ts`，并发为 1；单项测试上限 120 秒，整体上限 600 秒。超时时只结束本命令创建的测试进程树。工具仅运行指定范围内的测试，不提供额外的权限控制或沙箱隔离。

`pnpm test` 现在也使用此入口。每轮测试子进程使用独立空的 CODEX_HOME，避免自动项目创建的测试发现操作者的真实 Desktop 项目目录或认证状态；父进程和正在运行的服务环境不变。真实 Desktop 创建验收通过单独、显式的验证命令进行，不混入合成测试的通过数。这不是对任意子进程的完整网络或操作系统隔离。

完整日志写入本地 `releases/test-receipts/`（Git 已忽略），对话仅返回数值计数、退出状态、源文件清单哈希与日志哈希。任意测试正文、诊断堆栈、命令输出均不进入摘要。日志保留上限 16 MiB，截断会明确报告。原始日志应作为本地私有资料管理。文件权限设置不提供加密，Windows 上的 ACL 也需另行检查。

只有测试计数完整且一致、进程正常退出、无失败或取消项，且运行前后源文件集合一致，才会判定通过。跳过项独立列出，不能当作执行成功。源码指纹会重新枚举文件以发现新增/删除，也包含运行器本身；Git commit 不是唯一源码凭据，未提交更改通过 manifest hash 区分。
